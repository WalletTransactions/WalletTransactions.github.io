# Design

## Context

Сайт собирается MkDocs Material + `mkdocs-static-i18n` (папка на язык,
`fallback_to_default`), схемы рисуются mermaid через `pymdownx.superfences`.
Скриншотов в репозитории нет. Приложение и веб-кабинет показывают данные из
test-контура; после недавней полной зачистки там 0 операций и 31 счёт
стартового набора, так что без демо-данных кадры пустые (нули и `~?€`).

Android-телефон (Huawei) залогинен как `idranish.test@gmail.com`, Chrome по CDP
— как `idranish@gmail.com`. MCP-сервер `wallet-test` в сессии отклоняет токен.
См. proposal.md — мотивация.

## Goals / Non-Goals

**Goals:**
- Кадры, на которых видно живое приложение с правдоподобными данными.
- Один набор демо-данных для всех клиентов, чтобы цифры в приложении, вебе и ответе ассистента совпадали.
- Откат демо-данных после съёмки.

**Non-Goals:**
- Видео и анимации (GIF) — только статичные кадры.
- Скриншоты Telegram-бота.
- Автоматическая пересъёмка по CI: кадры снимаются вручную и обновляются вместе с релизами клиентов.

## Decisions

**Демо-данные льются через `/sync/push` на test-контур.** Генератор
детерминирован (`random.seed`), даёт 2 кошелька и около 500 операций с декабря
2025 по ноябрь 2026: летом кафе и поездки заметно дороже, чем зимой, чтобы вопрос
«лето против зимы» через MCP давал осмысленный ответ. Генератор и откат
(те же строки с `deleted: true`) хранятся вне репозитория сайта. Альтернатива —
писать в БД напрямую: отвергнута, потому что мимо `seq`/`change_stream` устройства
не увидели бы строки.

**Аккаунт — `idranish.test@gmail.com`.** Его леджер со стартовым набором уже
на телефоне, uuid категорий берутся оттуда. Требует входа Chrome под этим
аккаунтом (делает владелец: вход в Google не автоматизируется).

**Android — `adb screencap`, веб — CDP на ширине 375.** Строку состояния
Huawei через demo-режим не очистить (проверено: «Нет SIM-карты» остаётся), поэтому
верхняя полоса обрезается. Тёмная тема приложения оставляется, как есть.

**Ассистенты — снимок окна клиента.** LM Studio (локальный конфиг MCP) и Claude
(коннектор). Вопрос один и тот же в обоих: сравнение расходов на кафе летом и
зимой, чтобы страница не дублировалась разными примерами. Токен в кадр не
попадает: перед снимком окно настроек закрыто, адрес сервера скрыт.

**Русские и английские скриншоты.** Основной набор — русский в
`docs/ru/assets/shots/`; английский интерфейс снимается отдельно в
`docs/en/assets/shots/` с теми же именами. Где английского нет, работает
fallback на русский, а подписи и `alt` переведены в любом случае.

**Схема — mermaid, а не картинка.** Подхватывает светлую/тёмную тему и правится
диффом. Рамка «Ваш сервер» сделана `subgraph`, запись и чтение — двумя
вложенными `subgraph`, пунктир — для редких обращений в интернет.

**Страница — вкладки `pymdownx.tabbed`,** как на «Где пользоваться»; внутри
вкладки — сетка подписанных кадров (`md_in_html` + `attr_list`).

**Оптимизация.** PNG прогоняются через `oxipng`/`pngquant` до ≤300 КБ; при
необходимости — WebP. 8 Android-кадров + веб + 2 ассистента — порядка 2–3 МБ.

Затронутые сервисы: только `wallet-site`. OpenSpec `android-wallet`, `wallet-web`,
`wallet-mcp` править не нужно: поведение не меняется.

## Risks / Trade-offs

- [Кадры устаревают при редизайне клиентов] → подписаны версией приложения в описании PR; пересъёмка по задаче при смене интерфейса.
- [Демо-данные остаются на test и мешают тестам] → откат тем же файлом `deleted: true` сразу после съёмки; в PR перечислены затронутые строки.
- [На скриншот попадает лишнее: почта, адрес контура, токен] → проверка каждого кадра перед добавлением, критерий в спеке «Демо-данные на скриншотах».
- [Автоматизация входа Chrome невозможна] → шаг вынесен владельцу и зафиксирован в tasks.md.
- [`wallet-test` MCP отклоняет токен] → для кадров LM Studio/Claude нужен рабочий токен; без него вкладки ассистентов выходят позже остальных.
- [Первая запись нового пользователя провизионирует ему леджер, даже если батч упал] → при отладке посева учитывать побочный леджер; у `idranish@gmail.com` на test уже создан пустой.
- [`batch_id` в БД — uuid, хотя OpenAPI говорит «string»] → при посеве всегда генерировать uuid; расхождение вынесено отдельным замечанием в wallet-api.
